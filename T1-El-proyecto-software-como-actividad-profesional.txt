El proyecto como problema de decisiones

  Un proyecto software es un problema de decisiones, no solo de implementación.



Estas decisiones afectan a:

 ●   qué se va a hacer y qué no,
 ●   cuándo se va a entregar,
 ●   con qué recursos,
 ●   con qué nivel de calidad,
 ●   y con qué riesgos se está dispuesto a convivir.
Restricciones fundamentales de un proyecto

Todo proyecto software está condicionado, como mínimo, por cuatro grandes restricciones:

 ●   Alcance: qué funcionalidades o resultados se esperan del proyecto.
 ●   Tiempo: plazos, fechas límite, hitos intermedios.
 ●   Coste: recursos humanos, económicos y materiales disponibles.
 ●   Calidad: nivel de ﬁabilidad, usabilidad, mantenibilidad y robustez esperado.

El papel de los actores implicados

Un proyecto software involucra a múltiples actores, cada uno con intereses y responsabilidades distintas:

 ●   Cliente: deﬁne la necesidad y evalúa el resultado.
 ●   Usuarios: utilizan el sistema y determinan su utilidad real.
 ●   Equipo de desarrollo: implementa el software.
 ●   Responsable de proyecto: coordina, planiﬁca y toma decisiones.

Los conﬂictos entre actores son habituales:

 ●   el cliente quiere más funcionalidades,
 ●   el equipo necesita más tiempo,
 ●   los usuarios tienen expectativas no explícitas.

Gestionar un proyecto implica gestionar estos conﬂictos, no eliminarlos.
El rol del responsable de proyecto

El responsable de proyecto no es simplemente quien reparte tareas. Su función principal es:

 ●   tomar decisiones informadas,
 ●   anticipar problemas,
 ●   coordinar el trabajo del equipo,
 ●   y asumir la responsabilidad del resultado global.

Entre sus funciones se encuentran:

 ●   deﬁnir prioridades,
 ●   negociar con el cliente,
 ●   gestionar riesgos,
 ●   supervisar el avance real,
 ●   y decidir cuándo un proyecto está listo para avanzar o cerrarse.

Éxito técnico frente a éxito del proyecto

Es fundamental distinguir entre:

 ●    éxito técnico: el software funciona según lo esperado,
 ●    éxito del proyecto: el producto satisface las necesidades reales dentro de las restricciones
      acordadas.

Los criterios de éxito incluyen:

 ●    cumplimiento de plazos,
 ●    adecuación al presupuesto,
 ●    aceptación por parte del cliente y usuarios,
 ●    capacidad de mantenimiento y evolución.

La evaluación de un proyecto software debe hacerse desde una perspectiva global, no solo técnica.

Factores habituales de fracaso en proyectos

Numerosos proyectos software fracasan por causas recurrentes, entre ellas:

 ●   deﬁnición deﬁciente del alcance,
 ●   planiﬁcación poco realista,
 ●   comunicación inadecuada,
 ●   ausencia de seguimiento continuo,
 ●   falta de validación con el cliente o usuarios,
 ●   gestión deﬁciente de riesgos y cambios.

La mayoría de estos factores no están relacionados directamente con la programación, sino con la
gestión del proyecto.
Conclusión



Un proyecto software no se gestiona para que el código funcione, se gestiona para
                 que el proyecto tenga éxito en un contexto real.



       Si hay tantas personas y conﬂictos, ¿cómo nos organizamos para
